# Responsible AI at HANNAH

## Overview

HANNAH is a privacy-first, governed AI companion. This document outlines our transparency commitments, known limitations, and safety measures.

## Transparency

- **Model identification**: Every response identifies the model provider (Groq, Ollama, WebLLM, etc.) and model name.
- **Local vs. cloud**: The inference mode is always visible in the chat UI. Users know when their data leaves the device.
- **Audit trail**: All tool executions, memory changes, and configuration updates are logged in a hash-chained audit log (`hannah_audit.jsonl`).
- **Governance evidence**: Users can export a redacted compliance report of all audit entries.

## Limitations

- **Not a medical, legal, or financial advisor**: HANNAH is a software companion. It does not replace professional advice.
- **No emergency services**: HANNAH is not an emergency or crisis service. Users in distress should contact appropriate services.
- **Model hallucinations**: AI models can generate incorrect or misleading information. Users should verify critical information.
- **No guaranteed accuracy**: Responses are generated by probabilistic models and may contain errors.

## Safety Measures

### Human-in-the-Loop (HITL)
- All irreversible actions (file deletion, message sending, shell commands) require explicit user approval.
- SafetyGuard enforces confirmation dialogs before any sensitive operation.
- SideEffectLedger provides a 30-second undo window for all irreversible actions.

### GuardianAgent
- Zero-trust supervisor that evaluates every proposed tool call and proactive action.
- Assesses semantic intent (not just syntax) and detects multi-turn attack patterns.
- Configurable strictness levels: permissive, balanced, strict.
- Has final veto authority; all decisions logged to audit trail.

### Cognitive Risk Engine
- Scores every proposed action against CRF 2.0 dimensions: epistemic uncertainty, readiness deficit, behavioral vulnerability, consequence severity, intent uncertainty, memory uncertainty, environmental risk, action irreversibility.
- When risk exceeds threshold, the agent suppresses the action entirely and logs the suppression reason.

### Egress Policy
- Deny-by-default outbound network allow-list.
- Explicit allow-list entries required for each destination and request shape.
- All outbound calls validated against the policy before execution.

### Credential Broker
- Provider API keys held by CredentialBroker, never exposed to AgentRuntime.
- Credentials injected at network boundary and redacted from responses.

### Permission Monotonic Attenuation
- Once a permission is revoked during a session, it cannot be re-granted without new explicit user approval.
- Revocations persist for the session lifetime.

### Content Safety
- Prompt injection detection via red-team suite (100+ attack cases).
- Safety filters on both input and output.
- Memory poisoning prevention via GuardianAgent review.
- Proactive participation bounded by quiet hours, daily/weekly limits, and budget caps.

## Data Handling

- **Local-first**: Conversation history stays in browser/device. No server-side conversation database.
- **No PII collection**: The server does not store user conversations, messages, or personal data.
- **Audit log redaction**: All audit log entries are automatically redacted of credentials, user content, and sensitive data.
- **Encrypted sync**: Cross-device sync uses end-to-end encryption; the relay cannot read payloads.

## Limitations and Known Issues

- Speech recognition/synthesis depends on platform support (varies by device/browser).
- WebLLM requires WebGPU-capable browser.
- Native offline AI requires model download (iOS/Android only).
- Some features are scaffolds pending production hardening (see AUDIT.md).
